# 座標の入れ方（住所からの推定と `approx` の扱い）

スポットの緯度経度をどう決めるか、住所から推定するときの手順、
推定したものにどう印を付けるか。**推定した座標は必ず印を付ける**のが決まり。

関連: 台帳・JSONの列は [LEDGER.md](LEDGER.md)、現状は [HANDOVER.md](HANDOVER.md)。

---

## 1. どこから取るか（上から順に試す）

| 順 | 取り方 | 精度 | 印 |
|---|---|---|---|
| 1 | 台帳・調査JSONに書いてある座標（現地・公式・地図サイト由来） | 建物 | なし |
| 2 | 地図サイト（NAVITIME、Yahoo!マップ等）に載っている座標 | 建物〜数十m | なし |
| 3 | **住所から町丁目の代表点を引く**（下記） | 数十〜250m | `approx: true` |
| 4 | 取れない | — | 座標を持たない（一覧に「地図なし」で出る） |

**推測で置かない。** 「たぶんこの辺」で数字を作るくらいなら 4 にする。
座標が無くても一覧には出るし、ポップアップの「地図で開く」は名前でGoogleマップを
検索するリンクなので、場所はそこから辿れる。

> この作業環境からは地図APIに出られない（Google Maps も Nominatim も遮断されている）。
> 取れるのは GitHub と npm。だから 3 の道具を用意してある。

## 2. 住所から引く（推定）

使うのは [Geolonia の住所データ](https://github.com/geolonia/japanese-addresses)。
国土交通省「位置参照情報」由来で、ライセンスは **CC BY 4.0**。
raw.githubusercontent.com から市区町村ごとのJSONを取って、`.cache/geolonia/` に置く
（2回目からは通信しない。`.gitignore` 済み）。

```bash
# 引いてみるだけ
python3 scripts/geocode-jp.py 沖縄県那覇市壺屋1-6-16
→ 26.21303, 127.691621   壺屋一丁目の代表点   沖縄県那覇市壺屋1-6-16

# 取り込みのときに、座標の無いものだけ補う
python3 scripts/import-spots-json.py 追加.json --geocode
npm run build:spots && npm run check
```

補われたスポットには **`approx: true`** が付く。手で書く必要はない。

### 精度（実測）

**「◯◯二丁目」まである住所（市街地）** … 建物の座標が分かっている二郎系4店で比べた。

| 店 | ずれ |
|---|---|
| ラーメン二郎 京急川崎店 | 35m |
| ラーメン二郎 札幌店 | 50m |
| ラーメン二郎 横浜関内店 | 78m |
| ラーメン豚温泉 | 253m |

**「字◯◯」しかない住所（郡部の村など）** … 沖縄のホテル15件で比べた。

```
中央値 1,349m ／ 最小 451m ／ 最大 4,839m（オクマ）
200m以内 0件 ／ 500m以内 1件
```

字は集落まるごとなので代表点が遠い。**使えない。**
そのため `--geocode` は丁目・条まである住所だけを入れ、字しか無いものは
警告を出して飛ばす。どうしても入れたいときだけ `--geocode-aza`。

### 引けないとき

- **京都の通り名**（`中京区烏丸通御池下ル虎屋町566-1`）は当たらない。
  通り名を外した `中京区虎屋町566-1` の形で渡せば引ける
- 番地しか無い住所、新しい住居表示、地名の異体字は当たらないことがある。
  そのときは座標を持たない（上の表の 4）

## 3. `approx` が付くと何が起きるか

- ポップアップの住所の下に **「地図の位置はおよそ（町名から。出典 Geolonia CC BY 4.0）」** と小さく出る
- それ以外の扱いは普通のスポットと同じ（ピンも出るし、距離の輪にも入る）
- `npm run check` が「座標が無いのに `approx` がある」を弾く

```json
{ "id": "OKI-MEN-005", "name": "ラーメン二郎 沖縄店",
  "lat": 26.21303, "lng": 127.691621, "approx": true, "region": "okinawa" }
```

## 4. あとから正確な座標に直す

**同じIDで座標入りのJSONを流し直すだけ。** `approx` は消える（キーごと入れ替わる）。

```bash
cat > fix.json <<'EOF'
[{ "id": "OKI-MEN-005", "cat": "飲食店", "sub": "麺類（二郎系・直系）",
   "name": "ラーメン二郎 沖縄店", "addr": "沖縄県那覇市壺屋1-6-16",
   "t1": 15, "t2": 30, "c1": 10, "c2": 20, "rain": "◎",
   "desc": "…", "age": "中学生～大人", "note": "…",
   "lat": 26.2130, "lng": 127.6916, "region": "okinawa" }]
EOF
python3 scripts/import-spots-json.py fix.json    # --geocode は付けない
npm run build:spots && npm run check
```

IDが同じなら上書きなので、記録（訪問状況・メモ）は消えない。

いま `approx` が付いているのは4件。

| ID | 店 | 引いた町名 |
|---|---|---|
| OKI-MEN-005 | ラーメン二郎 沖縄店 | 壺屋一丁目 |
| ODA-MEN-004 | ラーメン豚山 小田原店 | 栄町二丁目 |
| NGY-MEN-006 | ラーメン二郎 名古屋大曽根店 | 矢田四丁目 |
| NGY-MEN-007 | ラーメン大 名古屋店 | 錦二丁目 |

## 5. 出どころの表示

住所データは CC BY 4.0 なので、そこから引いた座標を公開する以上、出どころを書いておく。
**置き場所は「その座標を使っているポップアップの中」**（`approx` の行）と README。

```
場所  愛知県名古屋市中区
      地図の位置はおよそ（町名から。出典 Geolonia CC BY 4.0）   ← Geolonia はリンク
```

地図の下（Leafletの著作権表示）には**入れない**。1行に収まらなくなって、
スマホでシートのつまみに重なり、開けなくなる（実際にやってしまった）。
Leafletのコントロールは z-index 800台にいるので、`.panel` は 900 に上げて、
スマホでは著作権表示とズームをシートの上（`margin-bottom`）に逃がしてある。
