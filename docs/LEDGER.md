# 台帳（Excel）の作り方

新しいエリアやカテゴリを調べてリストを作るときに、この形で用意すれば
`scripts/import-ledger.py` がそのまま取り込める。

```bash
# 1エリア分の台帳
python3 scripts/import-ledger.py 台帳.xlsx --region nagoya
# エリアをまたぐ台帳（「エリア」列で振り分け。IDが一致する行だけ上書きし、他は消さない）
python3 scripts/import-ledger.py 台帳.xlsx --by-area
# カテゴリごと差し替える（台帳に出てくる地域のそのカテゴリを消してから入れる）
python3 scripts/import-ledger.py 関東飲食店.xlsx --by-area --replace-cat 飲食店
# 全地域からカテゴリを消すだけ
python3 scripts/import-ledger.py --purge-cat 飲食店
# 特定の列だけ既存に反映する（IDで突き合わせ。他の列は無視）
python3 scripts/import-ledger.py 沖縄台帳.xlsx --only season
# 取り込んだら必ず
npm run build:spots && npm run check
```

シート名は既定で `全スポット`。違うときは `--sheet` で指定する。

## 列の一覧

太字は必須。列名は「別名」のどれでもよい（台帳ごとの表記ゆれを吸収している）。
**列の順番は自由**。使わない列がいくつ混ざっていても無視されるので、調査用の
メモ列（調査ソースURL、評価確認状況、選定区分など）はそのまま残してよい。

| 列名 | 別名 | 中身 | 備考 |
|---|---|---|---|
| **ID** | | `NGY-SCI-001` のような一意の文字列 | **一度決めたら変えない**。記録はこれで紐づく。エリア略号-カテゴリ略号-連番 が慣例 |
| **大カテゴリ** | | 下の13分類のどれか | 表記ゆれは取り込み時に寄せる。新語はエラーになる |
| **施設・スポット** | 施設名 / 店名 | 表示名 | |
| 小カテゴリ | ジャンル | 自由記述 | ポップアップの見出しに「大カテゴリ ／ 小カテゴリ」で出る |
| 所在地 | 所在地・代表住所 | 住所 | 番地まで書いてよい。取り込み時に「都道府県＋市区町村」へ詰める |
| 緯度 / 経度 | | 世界測地系の10進数（例 35.455858） | **空でもよい**（空だと地図に出ず一覧に「地図なし」で出る）が、**入れたほうがよい**。番地入りの住所があれば [COORDS.md](COORDS.md) の手順でおよその座標を引ける |
| 電車_最短分 / 電車_最長分 | 公共交通_最短分 / 公共交通_最長分 | 整数（分） | **その地域の起点から**の概算 |
| 車_最短分 / 車_最長分 | | 整数（分） | 同上。一覧の並び順（近い順）に使う |
| 雨天対応 | | `◎` `○` `△` `×` のどれか | ◎ほぼ屋内／○屋内中心／△天候で楽しみが減る／×屋外中心 |
| 概要 | 概要・選定根拠 | 1〜2文 | ポップアップの本文 |
| 注意・組み合わせ | | 1〜2文 | ポップアップの注意書き |
| おすすめ年齢 | | 自由記述（例「未就学児～小学生」） | |
| GoogleMaps評価 | | 数値（例 4.3） | 空でよい。**推測で埋めない**。0や空欄は「評価なし」として扱う |
| 公式URL | 公式・調査ソース | URL | ポップアップの「公式サイト」ボタン |
| 特におすすめな月 | | 自由記述 | 下記の書式。空でよい |
| エリア | | 関東 / 沖縄 / 北海道 / 小田原 / 名古屋 | `--by-area` のときだけ必須。`北海道（札幌）` のようなカッコ書きは落として読む |

取り込まれない列（あっても無害）: 最寄り・アクセス、主な楽しみ、圏内判定、
レビュー件数、評価確認日、GoogleMaps検索URL、訪問状況、家族メモ、座標種別、
座標取得元URL、座標確認日、選定区分 など。

> 訪問状況と家族メモはアプリ側（KV）で持つので、台帳の値は読み込まない。

### 「特におすすめな月」の書き方

原文をそのまま表示しつつ、月を読み取って絞り込みに使う。次の書式なら読める。

```
7～8月（海水浴）
5月・10月（バラ）
3～5月・9～11月（収穫体験）
1～5月（いちご）／9～11月（いも・みかん）
11～4月（イルミネーション）        ← 年またぎは 11,12,1,2,3,4 に展開される
```

区切りは `・` でも `／` でもよい。カッコの中は自由。月が1つも読めないと警告が出る。

**あとから月だけ追記した台帳**を渡すときは `--only season` を使う。IDで突き合わせて
`特におすすめな月` だけを反映するので、他の列がどうなっていても既存の値は変わらない。

## 体験プログラムの調査（JSON）

Excelの台帳とは別に、体験タグはJSONで取り込む。IDで突き合わせて体験まわりだけを
入れ直すので、他の列には触らない。該当なしのスポットも含めて全件を渡してよい
（タグが空なら、前に付いていた体験の情報を消す）。

```bash
python3 scripts/import-experience.py ~/体験調査.json
npm run build:spots && npm run check
```

```json
[{ "id": "S001",
   "experience_tags": ["科学・実験教室", "ものづくり・工作", "ガイドツアー"],
   "experience_memo": "小学生向けの実験・工作教室やアテンドツアーを開催。",
   "experience_age": "主に小学生。未就学児は保護者同伴で参加できる回あり。",
   "experience_programs": [{ "name": "MMサイエンスクラブ", "target_age": "小学生" }],
   "primary_source_urls": ["https://example.com/event.html"] }]
```

| キー | 中身 | 取り込み後 |
|---|---|---|
| **id** | 既存のスポットID | 突き合わせに使う。無いIDは警告を出して飛ばす |
| experience_tags | タグの配列。該当なしは `[]` か `"該当なし"` | `xtags`（原文）と `xg`（下の12区分）になる |
| experience_memo | 1〜2文 | `xmemo` |
| experience_age | 対象年齢の自由記述 | `xage` |
| experience_programs | `name` と `target_age`。**先頭3つだけ**入る | `xprog` |
| primary_source_urls | 一次情報のURL。**1つだけ**入る（公式URLと同じものは飛ばす） | `xurl`（ポップアップの「体験の案内」） |

**取り込まない**もの（あっても無害）: summary、schedule、fee、reservation、
各プログラムの source_url、evidence_note、research_status、source_checked_at。
日程・料金・予約は変わりやすく、結局は公式を見ることになるので持たない。

タグの原文は自由でよい。取り込みのときに次の12区分へ寄せる（`scripts/import-experience.py`
の `GROUPS`。上から順に見て最初に当たったもの）。**どの区分にも寄らないタグは警告が出る**ので、
そのときはキーワードを足すか、タグの言い回しを揃える。

```
動物とふれあう / 農業・収穫 / 食・料理 / ものづくり・工作 / 科学・実験 / 天体・星空
自然・生きもの観察 / 文化・伝統 / アート・表現 / 仕事・職業体験 / 体を動かす / ガイド・解説
```

区分を足す・変えるときは `public/index.html` の `XGROUPS` も直すこと
（合っていないと絞り込みから漏れる。`npm run check` が突き合わせている）。

対象年齢の絞り込み（未就学児／小学生／中学生以上）は、台帳の**おすすめ年齢**から
自動で読み取る（`ages`）。専用の列は要らないが、「小学生中心（未就学児も可）」
「3～15歳」のように、年齢が分かる書き方にしておくこと。

## スポットの追加分（JSON）

Excelを作るまでもない数を足すときや、調べたものをそのままJSONでもらったときは
`scripts/import-spots-json.py`。IDが既にあれば上書き、無ければその地域の後ろに足す。
他のスポットは触らない。

```bash
python3 scripts/import-spots-json.py ~/追加.json
npm run build:spots && npm run check
```

キーは `data/spots.json` と同じ（`id` `cat` `sub` `name` `addr` `t1` `t2` `c1` `c2`
`rain` `desc` `age` `rate` `note` `url` `lat` `lng` `region` `season`）。
体験プログラムを一緒に書くときは、上の調査JSONと同じキー（`experience_*`、
`primary_source_urls`）をそのまま並べてよい。読み替えは同じ。

```json
[{ "id": "OKI-HOT-001", "cat": "ホテル・宿", "sub": "恩納村／ホテル直結ビーチ",
   "name": "リザンシーパークホテル谷茶ベイ", "addr": "沖縄県国頭郡恩納村字谷茶1496",
   "t1": 90, "t2": 125, "c1": 55, "c2": 80, "rain": "◎",
   "desc": "…", "age": "全年齢（子ども連れ向け設備・プログラムあり）",
   "rate": null, "note": "…", "url": "https://www.rizzan.co.jp/",
   "lat": 26.4634347, "lng": 127.8165148, "region": "okinawa",
   "experience_tags": ["マリン体験"], "primary_source_urls": ["https://…"] }]
```

- 住所は台帳と同じく「都道府県＋市区町村」に詰める（番地は落とす）
- `--geocode` を付けると、**座標の無いものだけ**住所から町丁目の代表点を引いて入れる。
  ずれる（市街地で数十〜250m）ので `approx: true` が付き、ポップアップに「およその位置」と出る。
  郡部の「字◯◯」は数kmずれるので入らない（詳しくは [COORDS.md](COORDS.md)）
- `rate` は `null`・0・空なら持たない（**推測で埋めない**）
- 上に無いキーは黙って捨てる（調査メモ、座標の出どころ、日程・料金など）
- カテゴリが13分類に無いと止まる

所要時間は**必ずその地域の起点から**測る。地域を足すときは
`data/regions.json` に id・表示名・起点の緯度経度・輪の半径を先に書く。

地域どうしは重なってよい（小田原と関東で14件重複）。ただし**IDが別なら記録も別**に
なるので、同じ施設を2つの地域に入れると訪問記録は共有されない。
