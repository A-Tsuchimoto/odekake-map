# おひさまマップ

地域ごとの起点から、家族で行けるスポットを地図で見て、行ったら記録を残すための
個人用ウェブアプリ。利用者は本人ひとり。スマホからの利用が主。

- 引き継ぎ・現状のまとめ … [docs/HANDOVER.md](docs/HANDOVER.md)
- 台帳（Excel）の列とカテゴリ … [docs/LEDGER.md](docs/LEDGER.md)
- コードを触るときの決まり … [CLAUDE.md](CLAUDE.md)

いまの収録は5地域・685件（うち飲食店93件）。

| 地域 | 起点 | スポット | 飲食店 |
|---|---|---|---|
| 関東 | 横浜市営地下鉄グリーンライン 高田駅 | 183 | 52 |
| 沖縄 | ゆいレール 県庁前駅 | 125 | 9 |
| 北海道 | JR 札幌駅 | 128 | 12 |
| 小田原 | JR 小田原駅 | 84 | 8 |
| 名古屋 | JR 名古屋駅 | 72 | 12 |

飲食店はジャンルで選んでいる（麺類39・焼肉31・コーヒー23）。Google Maps評価は未取得。

**地域が一番上の区切り**で、スポットは必ずどれか1つに属する。所要時間も距離の輪も、
その地域の起点から見たもの。画面右上のボタンで切り替える。記録は地域をまたいで1つ。

**地域どうしは重なってもよい**。同時には表示しないので困らない。実際、小田原の84件のうち
14件は関東にも入っている（生命の星・地球博物館、江の島など）。ただし**IDは地域ごとに別**なので、
関東で「訪問済み」にしても小田原側は候補のまま。同じ場所を両方で管理することになる。

Cloudflare Workers（静的アセット + Worker）で公開する前提。
バンドルもビルドも要らず、`public/` の中身がそのまま配られる。

- 地図は Leaflet + CARTO のタイル。フレームワークなし
- 地域とスポットは `public/spots.js`（`window.__REGIONS__` と `window.__SPOTS__`）に静的に持つ
- 訪問記録は Worker 経由で Workers KV に保存する
- サービスワーカーで、アプリ本体と地図タイルをキャッシュしてオフラインでも開ける
- ホーム画面に追加すればアプリのように開く（PWA）

## 構成

```
public/                   ← 静的アセット。ここがそのまま配られる
  index.html              地図本体。CSS・JSすべて内包。依存はLeafletのCDNのみ
  spots.js                地域とスポットのデータ。data/ から生成する
  sw.js                   オフライン用キャッシュ
  _headers                セキュリティヘッダとキャッシュ指定
  manifest.webmanifest    ホーム画面追加用
  icon-192.png / icon-512.png
src/
  index.js                Workerの入口。/api/records 以外は静的アセットに渡す
  records.js              GET/POST /api/records。X-Token で認証し、KVに読み書き
data/
  regions.json            地域と起点。所要時間と距離の輪の基準になる
  spots.json              スポットの元データ。ここを直して npm run build:spots
scripts/
  build-spots.mjs         spots.json → spots.js の生成と検査
  check-config.mjs        wrangler.toml の検査
wrangler.toml             Workerの設定とKVバインディング（設定の正はこれ）
.github/workflows/check.yml    push時にデータと設定を検査する（デプロイはCloudflare側）
```

## 公開の手順

GitHub連携で運用している（**Workers & Pages > Create > Workers > Import a repository**）。
push すると Cloudflare 側が `npx wrangler deploy` を走らせて出す。手元のCLIは要らない。

**Pagesではなく Workers として作ること。** Pages用の設定（`pages_build_output_dir`）で
Workers のビルドに流すと `Missing entry-point to Worker script` で必ず落ちる。

設定の正は `wrangler.toml`。バインディングを変えるときはこのファイルを直して push する。
例外は**あいことば（APP_TOKEN）**で、これはファイルに書けないのでダッシュボードで入れる。

初回にやること。

1. **KVを作る** — ダッシュボード左 **Storage & Databases > KV** で **Create instance**。
   名前は `odekake-map-records`。作った行に出る **Namespace ID**（32桁の英数字）をコピー
2. **IDを貼る** — `wrangler.toml` の `id = "..."` を差し替えて push。GitHubのWeb編集でよい。
   **必ず引用符で囲むこと。** 裸で書くとTOMLが壊れてビルドが落ちる
3. **あいことばを入れる** — Worker > **Settings > Variables and Secrets > Add** で
   Type は **Secret**、名前 `APP_TOKEN`、値は好きな文字列
4. **もう一度デプロイする** — シークレットは**入れただけでは既存のデプロイに効かない**。
   Deployments から最新をやり直すか、空pushする

`https://odekake-map.<自分のサブドメイン>.workers.dev` で開く。
スマホで開いて「ホーム画面に追加」。

初回だけ、パネルの「あいことば」に APP_TOKEN と同じ文字列を入れて「つなぐ」を押す。
以後その端末には保存され、記録は自動でKVに書かれる。

うまくいかないときは `/api/records` を直接開く。401なら正常（あいことば無しなので）。
500なら KV かシークレットが効いていない＝手順4のやり直し漏れ。

### デプロイが止まるとき

Worker > **Deployments**（または Builds）で失敗したものを開くとログが読める。
実際に踏んだものを含めて、よくあるのは次の4つ。

| ログに出るもの | 原因 | 直し方 |
|---|---|---|
| `Missing entry-point to Worker script` | Pages用の設定のままWorkersにデプロイした | `wrangler.toml` に `main` と `[assets]` を書く（今はそうなっている） |
| `Unable to parse` / TOMLの構文エラー | KVのIDのクオート忘れ | `id = "..."` と引用符で囲む。数字始まりの32桁なので裸で書くと壊れる |
| Worker名が合わない旨 | `wrangler.toml` の `name` と実際のWorker名が違う | ダッシュボードのWorker名に `name =` を合わせる |
| `npm install` あたりで失敗 | ビルドイメージのNodeが古い | `.node-version`（同梱）が効く。効かなければ変数に `NODE_VERSION=22` |

`npm run check` が push 前に同じ壊れ方を検出する。CIでも毎回走っている。

ビルド設定は **Settings > Build**。Build command は**空**、Deploy command は
`npx wrangler deploy`、Root directory は `/`。

### プレビュー（本番ブランチ以外）

別ブランチを push するとプレビューURLが出る。バインディングは本番と同じものを使うので、
**プレビューから書いた記録も本番のKVに入る**。試し書きするときは注意。

### 手元で動かす

```bash
npm install
cp .dev.vars.example .dev.vars   # APP_TOKEN=すきなあいことば に書き換える
npm run dev                      # http://localhost:8788
```

ローカルのKVは `.wrangler/` の中に作られる。本番のデータには触らない。

## 地域を増やす

台帳（Excel）から取り込む道具がある。`pip install openpyxl` が要る。

```bash
# 1. data/regions.json に地域を足す（id・表示名・起点・距離の輪）
# 2. 台帳を取り込む。その地域のスポットが丸ごと入れ替わる
python3 scripts/import-ledger.py ~/台帳.xlsx --region nagoya
#    住所に都道府県が入っていない台帳なら --pref 沖縄県 を足す
# 3. 生成と検査
npm run build:spots && npm run check
```

地域をまたぐ台帳（「エリア」列で分かれているもの）は `--by-area`。
この場合は**IDが一致するものだけ上書き**し、載っていないスポットはそのまま残す。

```bash
python3 scripts/import-ledger.py ~/飲食店.xlsx --by-area
```

カテゴリごと差し替えるとき（台帳を作り直したときなど）。

```bash
# 台帳に出てくる地域の「飲食店」を消してから入れる
python3 scripts/import-ledger.py ~/関東飲食店.xlsx --by-area --replace-cat 飲食店
# 全地域から消すだけ（入れ直す前の掃除）
python3 scripts/import-ledger.py --purge-cat 飲食店
```

**IDを変えると過去の記録は迷子になる**（記録はIDで紐づくため）。台帳を作り直して
IDの付け方が変わった場合、古いIDの記録はKVに残るが、どのスポットにも表示されない。

取り込みでやっていること。台帳ごとに表記がぶれるので、そこを吸収する場所を1つに寄せてある。

- カテゴリ名を11分類に統一（`科学館系`／`科学館・博物館` → `科学館・博物館` など）
- 列名のゆれを吸収（`電車_最短分` と `公共交通_最短分` など）
- 住所を「都道府県＋市区町村」まで詰める（`愛知県豊川市市田町` → `愛知県豊川市`）。
  郡は町村まで、政令市は区まで残す
- 「特におすすめな月」の自由記述から月を読み取る
- 同じ地域の中で座標が完全に一致する組を約50mずらす（地域をまたぐ重なりはそのまま）
- IDが他の地域とぶつかっていたら止まる

## スポットを増やす・直す

`data/spots.json`（と地域を増やすなら `data/regions.json`）を直してから、必ず生成し直す。

```bash
npm run build:spots   # public/spots.js を作り直す
npm run check         # 中身の検査だけ（CIが回しているのもこれ）
```

検査で弾いているのは、公開してから気づくと面倒なものだけ。
IDの重複、緯度経度の抜け、起点から250km超（region の付け間違い）、
`index.html` の `COLORS` にないカテゴリ（灰色ピンになる）、
座標が完全に同じ2件（ピンが重なってタップできない）。

地域1件の形（`data/regions.json`）。

```json
{ "id": "okinawa", "name": "沖縄",
  "center": { "name": "県庁前駅", "lat": 26.214387, "lng": 127.679357 },
  "rings": [10, 25, 50, 75] }
```

`center` が起点。スポットの所要時間はここからの概算で、距離の輪もここが中心。
`rings` は輪の半径(km)で、地域ごとに変えてよい（関東 10/20/30/40、沖縄 10/25/50/75、
北海道 10/25/50/100、小田原 5/10/20/30、名古屋 10/25/50/75）。
`id` は記録には出てこないので後から変えられるが、`spots.json` の `region` と揃えること。

スポット1件の形。空の項目はキーごと省いてある。

| キー | 意味 |
|---|---|
| `id` | S001 / OKI-SCI-003 のような一意のID。記録との突き合わせに使う。**変えないこと** |
| `region` | どの地域か。`data/regions.json` の `id` のどれか |
| `cat` / `sub` | 大カテゴリ（12種）／小カテゴリ |
| `name` / `addr` | 施設名／所在地 |
| `t1` `t2` / `c1` `c2` | 地域の起点からの公共交通・車の所要時間（最短・最長、分） |
| `rain` | 雨天対応 ◎＝ほぼ屋内 ○＝屋内中心 △＝天候で楽しみが減る ×＝屋外中心 |
| `desc` / `note` / `age` / `rate` | 概要／注意事項／おすすめ年齢／Google Maps評価 |
| `season` / `months` | 特におすすめな月。台帳の原文と、そこから読み取った月の配列 |
| `lat` / `lng` | 代表地点の緯度経度（世界測地系）。**無くてもよい**（下記） |

座標は施設位置か、公園・山・海岸などは主要入口や中心部の代表地点。範囲全体ではない。

`season` は台帳の自由記述をそのまま持ち（例 `7～8月（海水浴）`、`1～5月（いちご）／9～11月（いも・みかん）`）、
ポップアップに「おすすめ」として出す。`months` はそこから読み取った月の配列で、
絞り込みに使う。`11～4月` のような年またぎは `[1,2,3,4,11,12]` に展開する。
両方あるか、両方無いかのどちらかにすること（`npm run check` が見ている）。

月で絞り込むと、その月を含むスポットだけが残る。**月の情報が無いスポットは消える**ので、
1件も無い地域では選べないようにしてある（いまは5地域すべてに入っている）。
他の地域にも足すときは、台帳に同じ列を作って取り込み直せば、そのまま使えるようになる。

記録1件の形（KV。スポットIDをキーにしたオブジェクト）。

```json
{ "S001": { "ID": "S001", "訪問状況": "訪問済み", "訪問日": "2026-07-26",
            "満足度": "5", "家族メモ": "ロケットの模型に釘付けだった" } }
```

`訪問状況` は 候補 / 行きたい / 予定 / 訪問済み / 見送り のいずれか。この5つは
ピンの見た目とフィルタに直結しているので、増やすなら `STATUS` の定義も直すこと。

## 座標のないスポット

緯度経度は任意。空のスポットは**地図には出さず、一覧にだけ「地図なし」付きで出す**。
一覧をタップするとその場でカードが開き、地図のポップアップと同じように記録できる。
「地図で開く」は名前でGoogleマップを検索するリンクなので、場所はそこから辿れる。

いまは全件に座標がある（最初の飲食店台帳が座標なしだったときのための仕組み）。

## 絞り込みの操作

カテゴリと訪問状況のチップは、見出しの右の2つで一括操作できる。

- **すべて表示**: 全部を選んだ状態に戻す
- **すべて解除**: 全部を外す。**そこから見たいものだけタップする**のが早い

1つも選んでいないときは0件になるので、一覧にその旨と戻し方を出す。

## 表示の設定

- **ポップアップの大きさ**: 標準／大きめ／特大。幅も文字も一緒に大きくなる。
  **ポップアップ右上の `A−` `A＋`** で切り替えるのが早い。パネルの「条件」にも同じものがある。
  選んだ大きさは端末に覚える
- **施設名を地図に表示**（パネルの「条件」）: 地図上に名前を出す。出すのは中心に近い60件まで。
  全部出すと重いし読めないので、拡大すると表示される数が増える

## 壊してはいけないところ

- **スポットIDと記録の対応**。IDを振り直すと過去の記録が全部迷子になる
- **あいことば1つで全部が守られている**。`APP_TOKEN` が漏れると誰でも記録を書き換えられる。
  家族それぞれのログインが要るようになったら Cloudflare Access に替えること
- **`public/_headers` の CSP**。読み込み先を増やしたらここにも足す。
  足し忘れると手元では動いて本番でだけ黙って止まる
- **保存の粒度**。記録は毎回オブジェクト全体を丸ごとPOSTしている。件数が数百のうちは
  これで問題ないが、差分更新に変えるなら競合の扱いを決めてから
- **KVの結果整合性**。書いた直後に別端末から読むと古い値が返ることがある。
  複数端末で同時に編集する使い方に広げるなら、KVではなくD1に移すこと
- **オフライン時の書き込み**。今はネットワークが切れると端末側に控えるだけで、
  復帰後の自動再送はしていない。「つなぐ」を押すと取得はするが、控えは反映されない。
  ここは既知の穴（下のTODO参照）

元は手作りのExcel台帳5つ。関東は `高田駅_家族お出かけスポット統合` の拡張版
（100分前後〜150分帯を55件足したもの。IDは YS/YAQ/YSEA/YR/YF/YH/YP/YA/YG/YX 始まり）、
沖縄は `沖縄本島_県庁前発 家族お出かけスポット統合管理`、
北海道は `札幌駅発 家族お出かけスポット統合管理`（HOK- 始まり）、
小田原は `小田原駅発 60分圏`（ODA- 始まり）、名古屋は `名古屋駅発 120分圏`（NGY- 始まり）。
カテゴリ名は台帳ごとに表記が違ったので、11分類に揃えてある
（例: 科学館系／科学館・博物館 → 科学館・博物館）。

所要時間は休日昼間の概算で、渋滞や乗換で変動する。湘南・三浦・アクアライン・房総・
中央道方面は、休日や海水浴期に150分を大きく超えることがある。沖縄の公共交通は
路線バス中心で本数が少ない路線が多い。

Google Maps評価は沖縄125件を除く全件に入っている（2026-07-26〜27時点）。
沖縄は未確認のため空（推測では埋めない）。

おすすめの月があるのは関東61件・北海道64件・小田原69件・名古屋53件・沖縄34件。
飲食店には入っていない。

北海道の所在地は、台帳の住所から市区町村までに詰めてある（例: 札幌市北区北10条西8丁目
→ 北海道札幌市北区）。台帳側で郡が抜けていた1件と、住所ではなく登山口名が入っていた1件
（樽前山）は取り込み時に直した。

所要時間のスライダーの上限は、データの最大値から自動で決まる（いまは車175分・
電車240分）。遠いスポットを足しても、そこだけ絞り込めない状態にはならない。
